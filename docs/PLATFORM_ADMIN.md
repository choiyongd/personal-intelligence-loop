# 운영 계정 설정

운영 주소의 `/admin`에서 등록된 Supabase 이메일과 비밀번호를 사용합니다. 일반 독자 로그인과 관리자 세션은 별도이며, 기존 독자·구독·메일 데이터는 기존 Supabase 연결을 계속 사용합니다.

1. 관리자 계정용 Supabase 프로젝트에 `20261115000100_platform_admin.sql`을 적용합니다. 기본 마이그레이션에서 만든 `private` 스키마와 `pil_worker` 역할이 필요합니다. 이미 초기화와 관리자 권한 부여를 완료한 프로젝트에는 SQL을 다시 적용하지 않습니다.
2. 이메일 인증을 마친 계정의 Supabase Auth UUID를 확인하고 SQL Editor에서 `select private.grant_platform_admin('<사용자 UUID>'::uuid);`를 실행합니다. 권한을 회수하려면 `private.platform_admins`의 해당 행을 제거합니다.
3. 배포 환경에 `ADMIN_SUPABASE_URL`과 해당 프로젝트의 `ADMIN_SUPABASE_PUBLISHABLE_KEY`를 설정합니다. 키는 `sb_publishable_` 유형을 사용합니다. 기존 고객용 Supabase 환경변수는 유지합니다.

가입 고객 수는 관리자 계정용 프로젝트에서 이메일 인증을 완료한 일반 회원 기준입니다. 별도 베타 독자·메일 통계와 합산하지 않습니다. 수익성은 운영자가 입력한 원화 금액을 기준으로 계산하며 결제 내역과 자동 합산하지 않습니다. 앱은 고객용 데이터베이스 연결에 문제가 있어도 권한 확인에 성공한 관리자에게 수익성 화면을 표시합니다.

기존 공용 운영 비밀번호와 그 인증 쿠키는 이 버전에서 사용하지 않습니다. 이전 운영 배포에 대한 롤백이 더 이상 필요 없을 때 호스팅 환경의 공용 운영 비밀번호를 제거할 수 있습니다.
